# 2026-10-12 Burnly v0.1.37 Release

## Objective

Prepare, validate, publish, and inspect Burnly `v0.1.37`: the release that cuts
refresh disk and memory costs by skipping stored OpenCode session history,
skipping unchanged Antigravity conversation files, scoping collector SQLite
connections to refresh jobs, and pruning expired `import_runs`.

## Risk Class

`high` — this changes ingestion and database connection lifetimes across
collectors, creates a version tag, executes signed multi-platform builds, and
promotes a GitHub release consumed by the desktop updater.

## Release Contract

- `package.json`, `src-tauri/Cargo.toml`, and the Rust lockfile agree on
  `0.1.37`; tag identity is `v0.1.37`.
- Release notes describe OpenCode scoped collect, Antigravity unchanged-file
  skipping, collector connection scoping, import run retention, and the reverted
  compositing trial.
- Local full and fast gates pass from a clean release commit.
- `development` is pushed and merged to `main`, and remote verification succeeds
  on the release commit before tagging.
- The tag points at the verified mainline release commit.
- All five platform builds, updater signatures, checksum manifests, provenance,
  and draft publication succeed.
- The draft notes and asset matrix are inspected before public promotion.
- Publication is recorded and this plan is archived.

## Checklist

- [ ] Write the release execution plan.
- [ ] Push `development`, open PR to `main`, and confirm CI verification passes.
- [ ] Merge PR to `main` and confirm remote verification on `main`.
- [ ] Create and push annotated tag `v0.1.37` on the verified mainline commit.
- [ ] Monitor release workflow (`validate`, 5 `build` matrix targets, `publish`).
- [ ] Inspect draft release notes, asset matrix, sizes, signatures, and checksums.
- [ ] Promote the draft release publicly (`--draft=false`).
- [ ] Record release evidence and archive this plan.

## Rollback And Stop Conditions

- Do not move or recreate an already-pushed tag. Fix forward with a new patch
  version if published inputs are wrong.
- Do not publish a partial matrix or a release missing updater signatures,
  checksums, installer helpers, or either updater manifest.
- Publishing is irreversible from an updater-consumer perspective; release
  deletion is not treated as rollback.

## Test Plan

- Release-specific commands:
  - `pnpm release:version v0.1.37`
  - `pnpm release-workflow:check`, `pnpm packaging:check`,
    `pnpm release-artifacts:test`, `pnpm updater-metadata:test`
- Full gates: `pnpm verify:fast`, `pnpm verify`
- Remote evidence: verify workflow runs on PR and `main`, then the release
  workflow for `v0.1.37`.

## Decisions

- Release from a `development` -> `main` merge, matching the repository's normal
  branch workflow, so `main` and the tag carry the same verified commit.
- Keep the Linux compositing mode variable unset following measured AppImage
  evidence.
