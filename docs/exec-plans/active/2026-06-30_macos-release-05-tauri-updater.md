# 2026-06-30 macOS Release 05 Tauri Updater

## Objective

Enable Settings-tab updates for the unsigned macOS preview by publishing signed
Tauri updater archives alongside the human-installed `.dmg` artifacts.

This builds on the unsigned macOS `.dmg` preview work. The `.dmg` remains the
first-install artifact; the updater consumes a separate `.app.tar.gz` archive
signed with the existing Burnly Tauri updater key.

## Acceptance Criteria

- macOS release targets stage both:
  - `burnly-vX.Y.Z-macos-aarch64.dmg`
  - `burnly-vX.Y.Z-macos-aarch64.app.tar.gz`
  - `burnly-vX.Y.Z-macos-x86_64.dmg`
  - `burnly-vX.Y.Z-macos-x86_64.app.tar.gz`
- Each macOS `.app.tar.gz` updater archive has a matching `.sig` generated by
  the existing Tauri updater signing key.
- `latest.json` includes `darwin-aarch64` and `darwin-x86_64` platform entries.
- macOS runtime reports update support available and uses `TauriUpdateRuntime`.
- Linux and Windows updater behavior remains unchanged.
- Harness coverage verifies macOS updater artifacts, signatures, and metadata.

## Design Review

- What complexity is introduced?
  - One additional macOS artifact per architecture and a platform-key mapping
    from canonical release target metadata (`macos`) to Tauri updater metadata
    (`darwin-*`).
- Which decisions stay hidden inside owning modules?
  - Artifact naming remains owned by `release-targets.json` and staging scripts.
  - Updater platform selection remains owned by updater manifest scripts.
  - Runtime capability selection remains owned by `bootstrap.rs`.
- Why not use `.dmg` as the updater artifact?
  - The `.dmg` is a human installer. Tauri updater expects an app archive payload
    and signature, so the updater points to `.app.tar.gz`.
- Which signing key is used?
  - The same Tauri updater key already configured for Linux and Windows:
    `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.
  - This is not Apple Developer ID signing and does not notarize the app.

## Runtime Evidence Required Later

This implementation can validate scripts and Linux-compiled Rust code locally,
but true macOS updater evidence still needs a real Mac:

- Install unsigned `.dmg`.
- Clear quarantine once.
- Launch Burnly.
- Verify Settings sees an update from a test `latest.json`.
- Install and restart through Settings.
- Confirm the updated app launches without another quarantine workaround.
- Repeat on Apple Silicon and Intel before calling macOS updater support
  production-ready.
