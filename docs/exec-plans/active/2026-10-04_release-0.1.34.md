# 2026-10-04 Burnly v0.1.33 Release

## Objective

Prepare, validate, publish, and inspect Burnly `v0.1.33`: the first release whose
Linux AppImage passes the AppImageHub catalog test, together with DeepSeek
Harness collection and attribution-truthful tray model rows.

## Risk Class

`high` — this changes public release metadata, creates a version tag, executes
signed multi-platform builds on newly changed runners, and promotes a GitHub
release consumed by the desktop updater and by the AppImageHub catalog.

## Release Contract

- `package.json`, `src-tauri/Cargo.toml`, and the Rust lockfile agree on
  `0.1.33`; tag identity is `v0.1.33`.
- Release notes describe DeepSeek Harness collection and its experimental cost
  limitation, the tray model row split, and the Linux AppImage portability fix.
- Local full and fast gates pass from a clean release commit.
- `development` is pushed and merged to `main`, and remote verification succeeds
  on the release commit before tagging.
- The tag points at the verified mainline release commit.
- All five platform jobs, updater signatures, checksum manifests, provenance,
  and draft publication succeed.
- The Linux AppImage legs build on `ubuntu-22.04` / `ubuntu-22.04-arm` and the
  AppImage smoke test passes there, proving the glibc 2.35 ceiling on a real
  22.04 artifact.
- The draft notes and asset matrix are inspected before public promotion.
- After promotion, `/retest` is commented on AppImage/appimage.github.io#7254.

## Rollback And Stop Conditions

- Do not move or recreate an already-pushed tag. Fix forward with a new patch
  version if published inputs are wrong.
- Do not publish a partial matrix or a release missing updater signatures,
  checksums, installer helpers, or either updater manifest.
- If the Linux smoke test fails on the 22.04 baseline, the glibc ceiling
  assumption behind this release is wrong: stop, leave the release as a draft or
  absent, and diagnose before promotion.
- Publishing is irreversible from an updater-consumer perspective; release
  deletion is not treated as rollback.

- Remote evidence: the verify workflow on the pull request and on the `main`
  push, then every job of the release workflow run for `v0.1.33`.
- Catalog evidence: the AppImageHub test comment on the pull request after
  `/retest`.

## Decisions

- Release from a `development` -> `main` merge, matching the repository's normal
  branch workflow, so `main` and the tag carry the same verified commit.
- The Linux AppImage is the release's reason for existing, so its smoke test
  passing on the 22.04 runner is a promotion gate rather than a nice-to-have.
- DeepSeek Harness ships as an experimental source and the notes say so, because
  every currently observed route reports cost as unavailable.
