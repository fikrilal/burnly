# 2026-10-03 Burnly v0.1.32 Release

## Objective

Prepare, validate, publish, and inspect Burnly `v0.1.32`, introducing Antigravity
empty CLI conversation tolerance, preventing false-positive runtime_not_found warnings
and source.not_found refresh failures.

## Risk Class

`high` — this changes public release metadata, pushes protected release inputs,
creates a version tag, executes signed multi-platform builds, and promotes a
GitHub release consumed by the desktop updater.

## Release Contract

- `package.json`, `src-tauri/Cargo.toml`, and the Rust lockfile agree on
  `0.1.32`; tag identity is `v0.1.32`.
- Release notes describe Antigravity empty session handling, offline SQLite
  conversation tracking, and the unsigned Windows/macOS preview warnings.
- Local full, runtime, and release-specific gates pass from a clean release
  commit.
- `development` is pushed and merged through the repository's normal protected
  branch workflow; remote verification succeeds on the release commit.
- The tag points at the verified mainline release commit.
- All platform jobs, updater signatures, checksum manifests, provenance, and
  draft publication succeed.
- The draft notes and asset matrix are inspected before public promotion.

## Rollback And Stop Conditions

- Do not move or recreate an already-pushed tag. Fix forward with a new patch
  version if published inputs are wrong.
- Do not publish a partial matrix or a release missing updater signatures,
  checksums, installer helpers, or either updater manifest.
- If verification or a platform build fails, leave the release as a draft or
  absent, diagnose, and require the corrected commit to pass before promotion.
- Publishing is irreversible from an updater-consumer perspective; release
  deletion is not treated as rollback.
