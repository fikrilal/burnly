# 2026-10-11 Burnly v0.1.36 Release

## Objective

Prepare, validate, publish, and inspect Burnly `v0.1.36`: the release that
restores deterministic tray panel placement on Linux Wayland sessions through
XWayland selection and pointer-monitor corner placement, after the `v0.1.35`
attempt failed to build outside Linux.

## Risk Class

`high` — this changes startup behavior on Linux, creates a version tag, executes
signed multi-platform builds, and promotes a GitHub release consumed by the
desktop updater.

## Release Contract

- `package.json`, `src-tauri/Cargo.toml`, and the Rust lockfile agree on
  `0.1.36`; tag identity is `v0.1.36`.
- Release notes describe the Wayland placement fix, the pointer-monitor change,
  and the `GDK_BACKEND` override.
- Local full and fast gates pass from a clean release commit, including a local
  check of the non-Linux compile path that the aborted attempt lacked.
- `development` is pushed and merged to `main`, and remote verification succeeds
  on the release commit before tagging.
- The tag points at the verified mainline release commit.
- All five platform builds, updater signatures, checksum manifests, provenance,
  and draft publication succeed — including the Windows and macOS legs that
  failed on `v0.1.35`.
- The draft notes and asset matrix are inspected before public promotion.
- Publication is recorded and this plan is archived.

## Attempt 1 (v0.1.35) Aborted

`v0.1.35` was tagged on `7611064` and its release workflow ran (`38130474334`).
`validate`, the Linux x86_64 build, and the Linux aarch64 build succeeded; the
Windows x86_64 and both macOS builds failed in `Build bundle`:

```text
error[E0425]: cannot find value `x_display_reachable` in this scope
```

The X display probe was defined only under `#[cfg(target_os = "linux")]` while
`select_display_backend` references it inside a runtime `cfg!` branch, which
still compiles on every platform. The `publish` job was skipped, so nothing was
published and no partial matrix exists.

`828e559 fix(platform): compile display backend selection on all platforms`
removes the outer platform gate so the probe exists everywhere; the inner cfg
blocks keep the real probe Linux-only and return `false` elsewhere. A module
compile with the platform cfgs inverted exercises the non-Linux branch locally.

Per the rollback contract the pushed `v0.1.35` tag is left in place and not
moved. The release is fixed forward as `v0.1.36`.

## Rollback And Stop Conditions

- Do not move or recreate an already-pushed tag. Fix forward with a new patch
  version if published inputs are wrong; this plan exists because of exactly that
  rule applied to `v0.1.35`.
- Do not publish a partial matrix or a release missing updater signatures,
  checksums, installer helpers, or either updater manifest.
- If the X11 backend selection regresses Linux startup or placement, stop before
  tagging and fix on `development`; the change is Linux-only and
  source-revertible before release, but never by moving a tag after publication.
- Publishing is irreversible from an updater-consumer perspective; release
  deletion is not treated as rollback.

## Decisions

- Release from a `development` -> `main` merge, matching the repository's normal
  branch workflow, so `main` and the tag carry the same verified commit.
- Fix forward as a new patch version instead of moving or recreating the failed
  `v0.1.35` tag.
- Keep the Linux-only behavior in the probe's inner cfg blocks rather than
  duplicating a non-Linux stub of the whole module.
- The release notes document `GDK_BACKEND` as the supported override instead of
  adding a product-specific setting.
