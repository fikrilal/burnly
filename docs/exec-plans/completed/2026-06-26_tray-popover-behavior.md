# 2026-06-26 Tray Popover Behavior

## Objective

Make the tray panel behave like a proper popover instead of an undismissable,
centered, frameless window. Fix the reported problems: no way to close, no way to
move, and it sits stuck at screen center.

## Acceptance Criteria

- The panel auto-hides when it loses focus (clicking elsewhere dismisses it).
- `Escape` hides the panel.
- A visible close affordance hides the panel.
- The panel header is a drag region, so it can be moved.
- Re-triggering the tray "Open Summary" action toggles (hides) a visible panel.
- The panel opens near the top-right of the active monitor, not screen center.
- A typed `hideTrayPanel` IPC command exists (mirrors `openDetails`) and is the
  only way the frontend asks to hide the panel (no direct Tauri APIs in React).

## Risk Class

`medium`

Changes a shipped product surface and the native window lifecycle; adds an IPC
command (contract regeneration).

## Impact Areas

- `src-tauri/src/platform/lifecycle.rs` (open/toggle/position/hide, blur handler)
- `src-tauri/src/bootstrap.rs` (window `Focused(false)` event)
- `src-tauri/src/application/ports/window_actions.rs` (port method)
- `src-tauri/src/ipc/commands.rs` + `ipc/mod.rs` (new command)
- `src/ipc/generated/contracts.ts` (regenerated) + `src/ipc/client.ts` (wrapper)
- `src/features/tray/TrayPanel.tsx` (drag region, close button, Escape)

## Design Review

- What complexity is being introduced? A hide path symmetric to the existing
  open path, plus a blur-driven auto-hide; no new product rules.
- Which decisions are hidden inside the owning module? Positioning and the
  blur/Escape/close dismissal all live behind `lifecycle` + the IPC command.
- Is each new interface simpler than its implementation? Yes — the frontend
  calls `hideTrayPanel()`; platform owns the window mechanics.
- What special cases exist, and can the design eliminate them? Blur-hide is
  scoped to the tray-panel window label; other windows are unaffected.

## Test Plan

- Behavior and invariants to prove:
  - Rust: open creates the panel; a second open hides a visible panel; blur hides
    the tray panel only.
  - IPC: `hideTrayPanel` invokes the `app_hide_tray_panel` command and parses the
    response (client test).
  - Frontend: existing tray tests still pass; Escape/close call the hide command.
- Lowest stable test layer: Rust unit tests (lifecycle), client unit test, RTL.
- Runtime evidence: `pnpm test:e2e` (desktop unaffected); manual tray check.
- Relevant commands: `pnpm rust:test`, `pnpm test`, `pnpm verify:fast`.

## Decisions

- Popover model (Option A), confirmed with the product owner.
- Frontend hides via a typed IPC command, not direct Tauri window APIs, to honor
  the architecture boundary.
- Positioning: top-right of the active monitor (reliable across Linux DEs) rather
  than tray-icon anchoring, which is unreliable on Linux.
